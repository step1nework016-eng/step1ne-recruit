# E21｜WSL2：電話錄音檔 → 準確逐字稿 → 自動進人選卡片（2026-10-09 Jacky 核准）

## 結論先講
Jacky 用 iPhone 錄電話，iPhone 內建轉文字錯字很多（頂薪→鼎新、上週→商周…），曾讓顧問誤判人選經歷。
要做：**Jacky 把錄音檔分享到 TG（訊息打人選名字）→ 這台用較準的語音辨識轉文字 → 交給既有的電洽整理流程 → 進人選卡片 → TG 回一則摘要**。Jacky 只做「分享錄音檔」一個動作。

## 已經上線、可以直接接的（Mac 10/9 做好）
- 後台 `/admin/application/call-summary`（mode=transcript）會把逐字稿接進 `consultant_call_notes`、記一筆電洽紀錄，並排 `call_notes_summary`。
- 排隊時已附上該人選的**履歷＋職缺**當背景（payload.context），`ai_worker.prompt_call_notes_summary` 會先校正專有名詞，**公司歸屬聽不清就標「請顧問確認」、禁止用履歷推斷**。
- 所以這台只需要負責「錄音檔 → 盡量準的逐字稿」，然後呼叫 call-summary（跟顧問助理 `consultant_ops.py summary` 同一條路，走確認卡讓 Jacky 按「寫進卡片」）。

## 要做的
1. **收檔**：TG 顧問助理（或你判斷更合適的入口）收到語音／音訊檔（iPhone 錄音多為 m4a）＋人選名字 → 用 `consultant_ops.py` 既有的人選解析（同名列清單問）。注意 TG Bot 下載上限 20MB，超過時回覆請 Jacky 改傳較短或壓縮的檔，並在回報說明有沒有更好的做法。
2. **轉文字（在這台本機跑，不要上傳到第三方）**：建議 faster-whisper large-v3（這台 16 執行緒、46GB，夠跑）。用 `initial_prompt` 餵**這位人選的履歷公司名、職稱、職缺名稱與必備技能裡的專有名詞**（T100、鼎新、BOM、Laravel…），提高專有名詞準確度。可以的話做說話者分段（顧問／人選）；做不到就先不分，回報說明。
3. **送進既有流程**：轉好的逐字稿用 call-summary（mode=transcript）送出，**走確認卡**，Jacky 按了才寫進卡片。
4. **錄音檔處理**：轉完就刪本機暫存檔，不長期保存錄音（個資）；只留文字。
5. **跟面談搶資源**：轉檔用 CPU、可能很重。**有阿財面談進行中時排隊等**（跟找人那套 NIGHTLY_WAIT_IDLE 同一個概念），不要拖慢阿財。

## 測試
- 用一段你自己錄的測試音檔（念一段含「鼎新 T100、商周集團、宣捷生技、BOM 表」的文字）比較：faster-whisper＋initial_prompt vs 不加 prompt 的錯字數。
- 實測 15 分鐘音檔轉完要多久、CPU 吃多少。
- 不要拿真實人選的錄音做測試；等 Jacky 傳第一個真的檔再驗。

## 規矩
- 不寄信、不傳訊息給人選；確認卡沒按就不寫卡片。
- 錄音檔不外傳到任何雲端轉錄服務（除非回報說明理由、Mac 核准）。
