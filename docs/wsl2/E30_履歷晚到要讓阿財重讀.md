# E30：履歷晚到（LINE 傳來）要讓阿財重讀——interview_daemon.py 小修

2026-10-12 Mac 交辦。Jacky 已核准整包「應徵表單流失修正」。

## 背景（一句話）

應徵表單多了「我用 LINE 傳履歷」：候選人可以先填表、做測驗，履歷從 LINE 晚一點才到。
Jacky 硬規則：**阿財開口前一定要讀過履歷**。面談入口（public worker `/chat/:token`）已經會擋「還沒收到履歷」的人。

## 還差的一塊（只有 daemon 能修）

daemon 會把候選人的資料快取住（`_STATIC_CACHE`）。如果快取的當下還沒有履歷、之後才從 LINE 收到，
`_late_refresh()` 只會補測驗跟初篩，**不會補履歷**——阿財整場都以為沒有履歷。
另外，`ready` 狀態的預熱開場白不看有沒有履歷，會先用「沒有履歷」的版本生好。

Mac 這邊先做了臨時補救（不動 daemon）：履歷晚到時，Worker 把 `prewarmed_at`／`interview_plan_at`
設成 `2000-01-01 00:00:00`，你的 `invalidate_stale_prepared()` 就會作廢重擬並清快取；
面談入口看到這個值會請候選人等一下（最多 5 分鐘）。這個補救有一個約 60 秒的空窗，下面的 patch 把它補起來。

## 要做的

```bash
cd ~/claude-projects/工作流程技能包/step1ne-recruit   # WSL2 上的路徑
git pull
git apply docs/wsl2/patches/interview_late_resume_refresh_20261012.patch
python3 -c "import ast;ast.parse(open('interview_daemon.py').read())"
# 重啟阿財 daemon
```

patch 內容（兩處）：
1. `_late_refresh()`：快取裡沒有可讀履歷時，每 30 秒看一次 `applications.resume_file_id／resume_url`；
   **換了一份**才整份重抓一次（抽不到字的圖片履歷不會每 30 秒重跑 fetch_application）。
2. `prewarm_candidates()`：還沒有任何履歷資訊的不預熱（Worker 反正會擋進房）。

## 驗收

- 拿一筆測試應徵（不要用真人）：先不放履歷 → 狀態改 ready → 確認 daemon 沒有預熱它。
- 補一份履歷（`/resume/?t=<chat_token>` 貼文字）→ 30 秒內 log 出現「🔄 …履歷是後來才收到的」。
- 做完把測試資料清掉，回報 Mac。
