# E38｜Jacky 10/20：帶案儀表板每天自動更新（WSL2）——10/20 22:50 改版：不需要 step1ne.com 的 token 了

## 先看這段（回應你的回報）
你回報「缺 step1ne-frontend-cf.env 停在步驟 2」——**已經改掉，不用那把 token 了。**
現在網頁（pipeline.step1ne.com）每次被打開時，會自己去 `step1ne-pipeline-data`（D1 那個帳號的小 Worker）讀最新資料。
所以 WSL2 只要定時跑 `build.py` 更新 D1 的 `pipeline_weekly`，**不用部署、不用 wrangler、不用新 token**。你原本就能寫 D1（`cf.env`）就夠了。

## 要做的
1. `git pull`（要拉到含「帶案儀表板改成網頁即時讀 D1」那個 commit）
2. 手動跑一次：
   ```bash
   cd ~/claude-projects/工作流程技能包/step1ne-recruit && python3 pipeline_dash/build.py
   ```
   看到 `本週已更新 2026-10-19 <時間>` 就成功（**不會**再出現「已上線」，那是正常的）。
3. 建 systemd user timer `step1ne-pipelinedash`：每天 **09:00、13:00、18:00、23:30** 跑上面那行，`Persistent=true`。週一 09:00 那次會自動封存上週。
4. 回報寫到 `docs/wsl2/回報/E38_回報.md`（覆蓋舊的）並 push：`systemctl --user list-timers | grep pipelinedash` ＋第 2 步輸出最後兩行。

## 不要做
- 不要加 `--deploy`（那是 Mac 改版面時用的，需要 step1ne.com 帳號 token，WSL2 沒有也不需要）
- 不要改 `pipeline_weekly` 裡 `frozen=1` 的週（封存的週報）
- 頁面有人選全名，不准動通行碼門禁

## 架構（給之後接手的人）
- `pipeline_dash/build.py`：D1 重算 → 存 `pipeline_weekly`（gz 壓縮）
- `pipeline_dash/data_worker/`：`step1ne-pipeline-data`（aiagentg888 帳號，綁 D1），只回給帶 `X-Pipe-Key` 的請求
- `pipeline_dash/worker.js`＋`template.html`：`step1ne-pipeline-dash`（step1ne.com 帳號），通行碼門禁，打開時去 data worker 拿資料套版
- 兩邊共用的鑰匙 secret `PIPE_KEY`，本機存在 `~/.config/workflow-os/step1ne-pipeline-data-key.txt`（只在 Mac）
