# E19 補：`d1q.py insert` 缺 must_check 編號直接報錯（E19 §6-1 核准，wsl2，2026-10-09）

程式 commit：見本檔所在 commit（`nightly_pipeline/d1q.py`、`nightly_pipeline/prompts/sourcing.md`）。**已併入 main，這台已拉新版，14:30 那輪找人就會用**。

## 改了什麼（白話）
- 夜間找人把人選寫進 `sourced_candidates` 時，如果模型**自己評 A 或 B**，那它的 `must_check` 必須把職缺的**每一條必要條件編號**都填進去，`status` 只能是 `met`／`unmet`／`unknown`。
- **缺任何一條編號、或 status 寫成別的字，整批都不寫入**，並且直接報錯：列出每位人選缺哪幾個編號、每個編號的條件文字，告訴它下一步（`python3 d1q.py conds <職缺代號>`，補齊後把同一筆重新 insert 一次；看不到的填 unknown，不要省略）。以前這種情況是靜默降成 C（10/9 培訓工程設計工程師漏填 1 條，2 位被降級、模型自己都不知道）。
- **一批裡只要有一筆有問題就整批不寫**，一次把所有有問題的人選報完（不會寫一半）。

## 刻意沒擋的（請確認這樣對）
- **自評 C／D 的不檢查**：本來就不該花時間寫進來，寫了也是 C／D，維持原樣。
- **職缺完全沒有必要條件**（連職稱、主要工作都沒填，`job_conditions` 回空）：不檢查。若只填了職稱，程式原本就會自動補 1 條「實際做過核心工作」，這 1 條也要填（編號 1）。
- **沒有個人頁的**照舊「不寫入、只記線索」，不算 must_check 問題（先過個人頁那關）。
- status 大小寫不同（`MET`）視為合法；只有真的不是 met／unmet／unknown 才報錯。
- 沒給等第也沒分數的，視為 D，不檢查；沒給等第但分數 60 以上，視為 B，要檢查（跟 `enforce_grade` 同一套算法）。
- `sourcing.md` 那句「沒附 must_check 的，程式一律當 C」已改成新規則的說明。
