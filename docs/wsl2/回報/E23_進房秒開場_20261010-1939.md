## 2. 進房後 96 秒到底在做什麼（照 log 與 D1 時間戳，沒有推測）
林小安（app `dd3cc10b`，2026-10-10）：
| 時間 | 事件 |
|---|---|
| 18:51:23 | `/apply` 建立（pending_assessment） |
| 18:53:56 / 18:53:57 | 交卷 / status→ready |
| 18:54:08 | 預熱開場白開始（交卷後 12 秒，在 daemon 輪詢撈到 ready 的那一輪） |
| **18:54:12** | **候選人進房**（Worker 當下沒有 `prewarmed_opening` 可貼，只貼了進房標記） |
| 18:54:53 | 預熱的 claude 呼叫結束（45 秒） |
| 18:55:10 | 預熱存檔完成（log「開場白已預熱」；claude 結束到存檔多了 17 秒，我沒追到這 17 秒花在哪） |
| **18:55:12** | **daemon 才開始處理這場**（`interview_host_at`） |
| 18:55:48 | 第一句出現（現場又生成了一次，claude 35 秒） |
**三個原因：**
1. **預熱太晚開始**：要等 ready（＝交卷）才撈得到，交卷後 12 秒才開始、約 60 秒才跑完，而候選人交卷後 15 秒就進房了。
2. **預熱佔住這場面談的鎖**：預熱走跟面談同一條路（`_busy` + DB 鎖 `lock_expires_at`）。進房那一刻預熱還在跑，`handle()` 搶不到鎖——**從 18:54:12 白等到 18:55:12（60 秒）**，等預熱結束才開始處理。
3. **預熱算好了卻沒用到**：預熱 18:55:10 存好，兩秒後 handle 開始，但 handle 完全不看 `prewarmed_opening`（只有 Worker 進房時會貼），所以又現場生成一次（35 秒）。
→ 96 秒 ≈ 60 秒（被預熱擋）＋ 36 秒（重新生成）。

## 3. E23b 改了什麼（`interview_daemon.py`，已上線）
