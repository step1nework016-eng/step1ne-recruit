原檔沒有處理「帳號底下同時連著多個 Chrome」的情況。實測這個帳號連著 4 個 Chrome

會一直卡住。所以在「瀏覽器規則」最前面加了第 0 條：

  `7d76c8d4-d2ea-47d3-b19e-a99ff8db6deb`（Windows 這台、使用者命名「win step1ne agent」的 Chrome）。
- 不可選別的 Chrome、不呼叫 `switch_browser`、不問人。
- 若 `select_browser` 失敗（那台沒連線）：不改用別台、不發 TG，直接結束，
  最後回覆寫「指定的 Chrome（win step1ne agent）沒有連線，今天沒有補資料」。

**⚠️ 這個 deviceId 的來源有一點推論**：使用者在 Chrome 擴充功能按 Connect 時，工具回報選到
「win step1ne agent」；之後 `list_connected_browsers` 列表上那台顯示名稱仍是 "Browser 1"，
我是用「這個 session 當下 inUse 的那一台（Windows、onThisComputer、最新連線）」對應過去。
另外該 deviceId 是在重新連線之後出現的新 ID，**之後如果 Chrome 擴充功能重新連線，
deviceId 可能會變**，變了的話排程會走到上面「沒連線→直接結束」的分支（不會誤用別台）。
需要有人（Jacky）定期留意；根本解法是把不用的 Chrome 從帳號斷開，只留這一台。
