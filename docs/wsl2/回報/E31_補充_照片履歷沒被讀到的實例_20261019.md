# E31 補充回報（WSL2）：照片履歷沒被讀到，面談時阿財看不到履歷（實例）

日期：2026-10-19 19:3x　　與 E31（多張截圖履歷一起讀）同一個問題，**需要總指揮決定照片履歷的文字辨識（OCR）由誰做**。

## 發生什麼事
- 一位人選（application `fac60f55…`，職缺 `bim-mep-drafting-engineer-hsinchu`）10/19 09:35 從 LINE 連結進來，傳的履歷是 **`IMG_6916.jpeg`（image/jpeg、237 KB、`storage=r2`）**。
- 19:23 他進面談室，阿財第一句就問「您的履歷我這裡看不到內容，方便先口頭介紹嗎？」。
- 他之後用語音回覆（3 秒），系統轉寫成「Thank you for watching.」（轉寫失敗），阿財請他改文字或重錄。

## 原因（查資料庫）
- `files` 這筆：`text_content = NULL`、`parsed_at = NULL`、`parse_note = NULL`、`chunks = 0` → **照片從來沒有被讀成文字**。
- `resume_read_checks` 沒有這位的紀錄 → 履歷讀取檢查沒觸發，也就沒有「讀不到」的提醒（LINE 通知／旗標）。
- 面談程式（`interview_daemon.py` 的 `context_for`）只吃 `resume_text`；文字是空的，就走「這場沒有履歷」的規則，所以阿財不是壞了，是沒有履歷文字可看。
- 這跟 E31 一樣：履歷是**照片／截圖**時，需要先做 OCR 才讀得到，而這一步目前沒有人負責上線（E31 時 Mac 要決定誰做，且這台缺 `recruit.env`）。

## 影響
- 只要人選用手機拍照或截圖當履歷，面談時阿財都看不到內容，只能口頭問；報告也會標「沒有履歷」，顧問要自己點開照片看。
- 這次是人選從 LINE 傳來，並且是「進房才發現」，沒有任何事前警示。

## 請總指揮決定
1. 照片履歷（jpg／png／截圖）的 OCR 由誰負責、放在哪一台跑（沿用 E31 的 A／B／C 選項）。
2. 在 OCR 上線前，是否先在 `resume_read_checks` 對「檔案是圖片且 `text_content` 為空」的人選推 LINE／TG 提醒，請人選補 PDF 或貼文字，避免到面談才發現。

WSL2 這邊沒有改任何東西（只讀查詢）。
