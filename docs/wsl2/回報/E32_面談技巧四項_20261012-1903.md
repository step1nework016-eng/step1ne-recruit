## 做法（跟 E24 的 `_pace_hints` 同一套：程式端數對話，直接告訴模型）
新函式 `_technique_hints(ctx)`，接在 `talk_prompt += _pace_hints(ctx)` 後面（對談每一輪都會算，TALK_LITE 與完整版都有）：
- **A 同一題不重問**：從阿財每則問句偵測 11 種主題（預告期、競業、出差、搬遷／通勤、薪資、離職原因／動機、空窗、數據分析、主導專案、談判、管理團隊），列出「這場已問過：預告期×2（已重複，不准再問）…」，並明講「已回答的題目即使很短，只能換角度追一次，不准同句或同義句重問；答得不夠記『回答偏簡短』交顧問電話補問」。
- **B 連兩次否定就換題**：同一主題候選人連續兩次答「沒有／不知道／沒做過…」（12 字以內）→ 「記為缺，直接換下一題，不要第三層，報告寫『本人表示沒有』」。不同主題的兩次否定**不會**被誤合併。
- **C 動機、搬遷必問（所有職缺）**：阿財問過 ≥3 個問題後，還沒問到「離職原因／動機」就提醒（在職追問一句推力＋拉力）；還沒問到「搬遷／通勤」就提醒（居住地跟職缺不同才問搬；同區問通勤）；寫明「時間不夠時這兩題優先於專業分級往上追問」。**不再受 `acai_v2` 限制**（原本 46 個職缺只開 2 個）。前 3 題不催，避免一開口就塞必問。
- **D 薪資最多兩次**：已問 1 次且答得模糊（面議／不方便／看情況，且沒有數字）→ 第二次換說法（區間選項或問現職待遇）；已問 2 次 → 「不准第三次，記『本人不願透露』交顧問電話」。
- **E 收尾用語**：出過英文題後，提醒只說「謝謝，英文這段我記下來了」，不說「英文可以清楚表達」「英文部分沒問題」這類結論。（羅文羿那場 10/12 阿財就說了「英文部分沒問題」。）

## 風險與限制（請 Mac 審時留意）
- 主題偵測是關鍵字／正則：沒抓到的說法就**不會提示**（寧可漏提示，不會誤擋）；寫法可能漏掉的例如把預告期講成「多久可以交接完」。上線後看 log 可再補詞。
- 「已重複」只在**問第二次之後**才出現，所以仍允許「換角度追一次」，不會把合理的第二問也擋掉；第三次才被禁。
- B 的否定判斷只看「很短的否定回答」（12 字內），候選人如果用長句說「我沒有做過這類分析」不會被算到（漏判，偏保守）。
- 提示會讓每輪 prompt 多約 300–600 字；API 版每輪輸入約 2.9 萬 token，增加不到 1%。
- E 項是提示詞層級的提醒；SKILL.md 裡若有「英文可以…」的範例句，建議 Mac 另外確認不要與這條衝突（我沒動 SKILL）。

## 追加 F（楊策淳 10/12 19:23，切 API 後第一場真實面談）——已併進同一份 patch
**現場**：候選人說「可以，但面談時間需要更改」→ 阿財問「是時間不夠、還是想約其他時段嗎？」（19:23:59，連同第二個氣泡「如果現在時間比較緊，我們可以先聊精簡一點」）→ **7 秒後（19:24:06）沒等回答就自己說「好，那我們抓精簡版」並問預告期**。

**我查到的原因（D1 訊息與 token_usage 對得上）**：這場有**兩次對談呼叫**（19:23:59 與 19:24:06），但候選人只有一則訊息（id 3085）。
1. **同一則候選人訊息被處理了兩次（race）**：主迴圈每輪先抓一份「待回清單」（`active_sessions()`），抓完到真正派工之間，上一輪的 `handle()` 剛好回完並放鎖，新一輪就用過時的清單搶到鎖、又回一次；第二次看到第一次的問句沒人回答，就替對方答了。`handle()` 取得鎖之後沒有重新確認「最後一則是不是還是候選人」。這個 race 跟走 API 或 CLI 無關（任何一輪的回覆剛好落在輪詢的空檔都可能發生），只是 API 回得快，空檔更常被踩到。
2. 第一次回覆的兩個氣泡本身就有「問完又假設答案」。

**patch 做了**：
- **過時清單保險**：`handle()` 取得鎖後，先查「最後一則（排除過渡語）是不是阿財」；是就略過這輪（log「↩️ 他已經被回過了」）。
- **改時間快速路徑**：候選人短訊息（≤60 字）表示要改面談時間／現在不方便（面談…時間…更改、現在不方便、改天、晚點再聊、換個時間…）→ 直接回「沒問題，我請顧問跟您約時間，不用急，謝謝您。」、**不呼叫模型**、TG 通知顧問（含他的原話與職缺），之後提示模型不要開新題。面談仍開著，他回來可以接續；沒人回就由既有的閒置收尾處理。
- **問了就要等回答**：硬規則加進每輪提示；另外事後擋——同一輪若某則以問句結尾、後面的氣泡都不是問句且是「如果…／那我們…／先聊精簡」這類假設對方答案的句型，後面的丟掉（log「✂️」）。
- 測試新增 20 項（含用假依賴驗證 `handle()` 在過時清單時不呼叫模型、不寫訊息；改時間時只寫一則固定句＋一則 TG、不呼叫模型）。

**限制／請 Mac 留意**：
- 改時間的偵測只看短訊息、關鍵字偏保守；工作上的「專案時間更改」「到職時間可以再談」「我晚點再想想」這類不會誤判（有測試）。漏判的話就走原本的模型流程。
- 過時清單那個保險只擋「我自己這個 daemon 重複處理」；兩台（Mac／WSL2）同時搶仍靠原本的 DB 鎖。
- 這個 race 是**線上真實存在**的 bug（今天就發生在真人候選人身上），建議 Mac 優先審這一部分；若要先上最小修，只要 `handle()` 開頭那個 8 行的重新確認即可。
- 楊策淳這場目前停在阿財問預告期（19:24）之後候選人沒回；顧問可能要確認他要約的時間。
