# 共用回報格式（紅隊／藍隊都用這一份）

這份定義「發現怎麼記、修補怎麼記、週報怎麼寫」。紅隊藍隊都寫進同兩張 D1 表：`sec_findings`、`sec_events`。
顧問後台 `/sec/` 儀表板只讀這兩張表（程式在 step1ne-backoffice-worker `/admin/sec/board`）。

---

## 1. sec_findings（一個漏洞一列）

| 欄位 | 說明 | 允許值／範例 |
|---|---|---|
| `id` | 主鍵 | uuid，沒給會自動補 |
| `title` | 一句話標題（給工程師看） | 例：`portal 可用別人的 case id 讀到他人履歷` |
| `area` | 受影響區塊 | `public-worker` / `backoffice-worker` / `messaging-relay` / `social-worker` / `recruit-worker` / `site-public` / `site-consultant` / `pick` / `sec` / `portal` / `acai`(阿財) / `afu`(阿福) / `background-ai` / `wsl2-host` / `mac-host` / `d1` / `r2` |
| `severity` | 嚴重度 | `high` / `medium` / `low` / `unknown`（評分規則見紅隊 SKILL 第 6 節） |
| `status` | 狀態 | `open`（紅隊剛找到）/ `fixing`（藍隊在修）/ `verified`（藍隊修好且紅隊複測通過）/ `wontfix`（決定不修，要寫原因在 fix_note） |
| `found_by` | 誰找到 | `red` |
| `found_at` | 找到時間 | 台灣時間 ISO 字串，沒給自動補 |
| `fixed_at` | 修好時間 | 藍隊填 |
| `verified_at` | 複測通過時間 | 紅隊填 |
| `plain` | **白話說明**（給 Jacky 看，不准術語） | 例：`我們的客戶專區，網址把「案件編號」改成別人的，就看得到別人的履歷，等於門沒鎖。` |
| `fix_note` | 修法摘要／不修原因 | 藍隊填 |
| `week` | 週別 | `2026-W41` 這種 ISO 週，方便週報彙整 |

**只插入不更新的環境限制**：WSL2 夜間用的 `d1q.py` 只能 `insert`（沒有 update 入口）。
所以狀態流轉（open→fixing→verified）要嘛由後台 `/sec/` 的管理動作寫、要嘛用專屬小工具；
**不要**為了改一個欄位去放寬 `d1q.py` 的白名單。紅藍隊若需要 update，向 Mac 總指揮要一支受限的 `sec_update.py`（只能改這兩張表的 status/fix_note/時間欄位）。

## 2. sec_events（一條時間軸事件，給 /sec/ 對打畫面跑動畫用）

| 欄位 | 說明 | 允許值 |
|---|---|---|
| `id` | 主鍵 | uuid |
| `team` | 哪一隊 | `red` / `blue` |
| `kind` | 事件種類 | `found`（紅隊找到）/ `fixed`（藍隊修好）/ `verified`（紅隊複測通過） |
| `finding_id` | 對應的 sec_findings.id | |
| `text` | 一句白話 | 例：`紅隊找到：portal 換個編號看得到別人履歷（高風險）` |
| `created_at` | 時間 | 自動補 |

計分（後台已寫死，紅藍隊不用自己算，但要知道）：紅隊找到得分 high30／medium15／low5／unknown10；
藍隊**只有** status=verified 才得同樣分數；「防禦值」＝100 −（還開著的漏洞分數總和），最低 0。

## 2.5 嚴重度硬規則（Jacky 指定，凌駕 CVSS 分數）

下面兩類資料只要「可能被未授權者看到」，**一律 `high`，不管 CVSS 算出來幾分**：

**① 人選個資（最高風險）**：履歷、電話、Email、薪資、面談逐字稿／初篩報告。

**② 公司職缺中「官網沒公開」的部分**（保密義務，比照 high）：
- 保密職缺的客戶公司名稱（如 `confidential_client` 之類欄位）
- 客戶窗口姓名／電話／Email
- 內部篩選條件（如 `client_screen_conditions`、`hard_filters` 等）
- 客戶內部薪資結構、年齡等「內部備註」欄位
- 合約／收費條款
- 尚未上架的職缺草稿（`client_draft`／`pending_review` 狀態）
- 客戶名稱、合約外洩同樣 `high`

**不算 high 的**：官網「已公開」的職缺頁內容本身（那本來就給大家看）。

凡命中 ①②，紅隊規則：**發現即停手、不下載或保存任何真實資料（只用一筆測試資料證明即可）、立刻寫 `sec_findings`＋`sec_events` 並發 🚨 TG 即時告警，不等週五。**（見下方 TG 管道與第 3 節）

## 2.6 TG 回報管道與訊息規則

- 路由：`tg_routes` 的 key = `security`，對應「HR AI招募自動化」群組 `-1003231629634`、thread `7421`。所有資安訊息都走這裡。
- 四種訊息：
  1. 🚨 **即時告警**：人選個資或職缺機密（§2.5 ①②）可能外洩時，當下就發，不等週五。
  2. 🔴 **週一攻擊結果摘要**：本週自我稽核做了哪些、找到幾個。
  3. 🔵 **修好並複測通過**：某 finding 藍隊修好、紅隊複測 `verified` 時發。
  4. 📋 **週五白話週報**：含「需要 Jacky 決定的事」（格式見第 3 節）。
- **TG 訊息禁止出現**：攻擊步驟或可重現方法、任何金鑰或權杖、任何人選真實資料（姓名／電話／Email／履歷內容／客戶名）。
- 只寫**白話結論**＋一句「細節看 https://step1ne.com/sec/（要登入）」。技術細節、重現方式、受影響 id 都只進 `sec_findings`（後台權杖才看得到），不進 TG。

🚨 即時告警範例（note：不含任何真資料與步驟）：
```
🚨 資安即時告警
發現一個可能讓外部看到「人選履歷／電話」的破口，已先擋下並停止進一步測試。
沒有下載任何真實資料，只用一筆測試資料確認。
藍隊開始修補中。細節看 https://step1ne.com/sec/（要登入）。
```

## 3. 週五 TG 白話週報格式（給非工程師看，先結論）

發到 `security` 路由（§2.6）。嚴格遵守：先講結論、不用術語、每條都能一眼看懂。

```
【本週資安體檢】2026-W41（10/06–10/12）

結論：這週防禦值從 72 升到 85，沒有正在被利用的破口。有 1 件要你決定。

這週發生什麼：
• 紅隊試圖闖入我們自己的系統 23 處，找到 3 個沒鎖好的地方。
• 藍隊修好 4 個（含上週留的 1 個），每個都經紅隊回頭確認真的鎖上了。
• 目前還開著 2 個：1 個中風險（排下週修）、1 個低風險（不急）。

白話講最重要那一個：
• 「客戶專區換個網址編號會看到別人的履歷」——就是 104 那種門沒鎖。已經修好並確認鎖上。

要你（Jacky）決定的（只有 1 件）：
• 顧問後台目前全部顧問共用同一把鑰匙（一組密碼）。要不要排時間改成「一人一把、會自動過期」？
  這是動到大家每天登入的方式，要你點頭才動。兩個選項：A 這個月排　B 先不動、先把其他小洞補完。

你不用管的（我會自己處理）：
• 其餘 5 個小設定（安全標頭、錯誤訊息太囉嗦、測試站殘留檔）我這週自己補完，不需要你決定。
```

週報三段式口訣：**結論 → 找到幾個／修好幾個／還開幾個 → 要你決定的（收斂成 1–2 個是非／二選一）**。
技術細節一律留在 `sec_findings`，週報不出現 CVSS、OWASP 編號、Worker 名稱這些詞。
