# 禁刊過濾器（完整版）

每一條都對應一次真實踩過的狀況。逐條比對來源 JD，命中就移除並記錄。

---

## 1. 委任客戶公司名稱

**規則**：客戶公司名稱一律不出現在公開頁面。

**為什麼**：獵頭與客戶之間有保密義務；公開客戶名等於讓同業知道你在服務誰、
也可能讓客戶方 HR 收到不預期的直接應徵。

**改寫方式**（保留對求職者有用的資訊，只拿掉識別）：

| 原文樣態 | 改寫 |
|---|---|
| 〈半導體大廠名〉銅鑼廠建廠專案 | 大型建廠專案／國際半導體大廠建廠專案 |
| 〈醫材集團名〉集團 | 製造業集團／跨國製造集團 |
| 〈遊戲集團子公司名〉 | 知名遊戲營運公司／電子支付公司／大型客服服務中心 |
| （〈客戶名〉相關專案廠區內） | （直接刪除這類括號備註） |
| 配合〈客戶名〉廠區 EHS 規範 | 配合廠區工安規範 |

> 上表刻意不寫出真實客戶名稱——這份文件本身也適用同一條規則。

**可以保留的**：工作地點（縣市/鄉鎮）、產業別（半導體/紡織/醫療器材）、
公司規模描述（跨國集團/上市公司）。這些是求職者判斷要不要投的必要資訊，
且不等於指名道姓。

**注意**：圖片裡的文字也算。若客戶名被畫進廣告圖／banner，改 HTML 沒用，
要重新出圖——這種情況要明確跟使用者說，不要當作已處理。

## 2. 歧視性條件（法律風險，最高優先）

**規則**：以下條件一律不得出現在招募廣告上。

依《就業服務法》第 5 條，雇主招募或僱用員工，不得以**種族、階級、語言、
思想、宗教、黨派、籍貫、出生地、性別、性傾向、年齡、婚姻、容貌、五官、
身心障礙、星座、血型或以往工會會員身分**為由予以歧視。違反者可處罰鍰。

**常見命中與改寫**：

| 來源寫法 | 為什麼不能刊 | 改寫 |
|---|---|---|
| 30 歲以下為主要條件 | 年齡歧視 | 歡迎職涯初期人才／歡迎具學習意願、可塑性高的人選 |
| 35 歲以下 | 年齡歧視 | 同上 |
| 馬來西亞籍/中國籍 ok | 國籍歧視 | **整條刪除**（若職缺確有工作權需求，改寫成「需具備台灣合法工作權」這種中性表述） |
| 限男性／女性佳 | 性別歧視 | 刪除；若確有體能需求，改寫成具體工作要求（例：需搬運 20 公斤以上物品） |
| 已婚未生育佳 | 婚育歧視 | 刪除 |
| 形象佳／需外型端莊 | 容貌歧視 | 刪除；若為門市/接待職，改「需具良好服務儀態」 |

**判斷原則**：如果條件描述的是「人的身分屬性」而非「工作能做什麼」，就是紅線。
把它翻譯成該屬性背後真正想要的**能力或條件**，再寫上去。

**這條不可以因為「客戶要求」而放行。** 廣告是刊在自家網站上，法律責任在自家。
若客戶堅持，回報給使用者由業務端處理，不要自行刊登。

### ⚠️ 良民證不是禁刊項——不要再當成法遵風險回報（2026-08-10 老闆確認）

良民證（警察刑事紀錄證明）確實屬《就業服務法施行細則》§1-1 第 3 款的隱私資料，
但法律**沒有禁止**，條件是**兩者同時成立**：

1. **求職者同意**
2. **就業所需**——為經濟需求或維護公共利益之必要且合理範圍

Step1ne 現行做法已符合：兩個條件都確認成立才要求，且**實際索取是在面試環節**，
不是應徵前置門檻。頁面上載明是為了提前告知，避免人選到面試才知道而白跑。

**所以掃到職缺頁寫著良民證時，不要報成違法、不要建議改寫。**
2026-08-10 曾把這件事當成 6-30 萬罰鍰風險回報給老闆，是誤報——
只查了「屬於隱私資料」就下結論，漏掉「同意＋就業所需即可要求」這半段。
要查的是那兩個條件成不成立，不是有沒有出現這三個字。

## 3. 內部獵頭搜尋策略

**規則**：給顧問看的 sourcing 策略不能出現在求職者頁面。

**典型內容**：
- 「理想人選（Ideal Candidate）：建議鎖定下列產業背景…」
- 「建議搜尋職稱：Finance Controller / Plant Finance Manager / Factory Controller…」
- 目標公司清單、競品挖角名單
- 「這個職缺可以從 XX 公司挖」

**為什麼**：這是你的方法論與情報。公開等於告訴同業你打算去哪裡挖人、
也告訴那些公司「有人在挖我的人」。

**可以轉化的部分**：搜尋職稱清單可以轉成**求職者自我對照**的敘述，例如
「若你目前的職稱是財務經理、工廠財務主管或類似角色，這個機會會是明確的一步」——
這對 SEO 長尾也有幫助，但要重寫成對求職者說話，不是照貼清單。

## 4. 內部溝通備註

**規則**：需求表裡顧問寫給自己/同事看的註記不刊。

**典型**：
- 「客戶最初印象數字為 25–30 位，與此次確認的 20 位有落差，建議書面二次確認」
- 「客戶窗口態度保守，需再確認預算」
- 「此職缺已開三個月未補齊」

這些會讓客戶看到很尷尬，也讓求職者對職缺產生疑慮。

---

## 5. 標註「待確認」或未提供的欄位

**規則**：來源標「待確認」的欄位，**不要刊登，也不要自己推測填補**。

**典型**：上班時間、休假方式、直接匯報對象。

**處理方式**：
1. 頁面上直接省略該欄位（不要寫「待確認」給求職者看，那看起來很不專業）
2. 列進 Phase 7 的「待你確認」清單，請使用者跟客戶確認後再補
3. 頁面底部保留這句：「※ 上述條件為目前規劃，實際待遇與工作條件依面試後雙方確認為準。」

**為什麼不推測**：工作條件寫錯會直接造成求職者到職後的爭議，這是誠信問題，
不是體驗問題。

## 6. 薪資揭露的判斷

薪資本身**應該**公開（對 SEO/AEO 有利，JobPosting schema 也吃），但揭露方式要判斷：

| 來源形式 | 刊登方式 |
|---|---|
| 單一數字或區間（月薪 4-5 萬） | 直接公開區間 |
| 依學歷/科系分級表 | **只公開總區間**（例：35,000–53,000），註明「依學歷與科系相關性核定」，不公開分級細節 |
| net USD 3,000–4,000 這類外幣淨額 | 公開，並加註「net 指稅後實拿」並換算台幣年薪區間 |
| 純「面議」無數字 | 頁面寫「依經驗面議」，schema 不放 `baseSalary` 欄位（放假數字比不放更糟） |

**為什麼分級表不公開**：把「普通大學 35K vs 前四大 43K」掛在網站上，
觀感上是學歷歧視，容易被截圖傳播，品牌風險大於揭露帶來的好處。
總區間已足夠讓求職者判斷要不要投。
