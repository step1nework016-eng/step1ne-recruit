# 競品職缺反查客戶——方法紀錄

> 2026-09-24 第一次做，Jacky 指派。目的：同業獵頭公司（不是 104 這種平台）會在自己
> 官網公開刊登受託職缺，把這些職缺讀出來、反推是哪家企業在找人，變成 Step1ne 的
> 開發名單。**每次要跑這件事之前，先讀這份，不要每次重新摸索一次網站結構。**

## 核心邏輯

同業獵頭公司公開刊登的職缺，本身就是「這家企業現在有招募需求，而且已經找了獵頭」
這件事的公開證據。對 Step1ne 來說，這比自己亂猜哪家公司在缺人準得多——
不用等對方主動找我們，直接從同業的官網就看得到誰在委託招募。

流程：**抓職缺 → 認出委託公司 → 過濾（排掉自己人客戶）→ 寫進開發名單 → 排優先順序**

## ⚠️ 界線（每次跑都要守）

- 只讀公開頁面：遵守 robots.txt、每個網站每秒最多 1 次、不登入、**遇到驗證碼或
  擋爬蟲就停，不繞過**（不換 UA 硬闖、不用代理、不解 CAPTCHA）
- 開發信裡絕對不能寫出「我們看到某某獵頭在幫你找人」——切角要照
  `references/開發信框架.md`，不能提到任何競品名稱
- 反推出來信心不高的（confidence: low），不要直接進 `draft_bd.py` 的寄信流程，
  先讓 Jacky 或顧問看過再說
- 寫進 `company_leads` 之後，**寄信前一定要再跑一次 `client_guard.py`**——
  這支只是把線索放進池子，不是開發名單本身，重複保護不嫌多

## 各家網站踩過的雷（照這個順序查，不要重新摸索）

### 1. HuntByte（huntbyte.com）—— ⭐ 目前最好用的來源

- Sitemap：`https://www.huntbyte.com/sitemap.xml` 是索引，職缺在子項
  `https://www.huntbyte.com/sitemap-jobs.xml`（2026-09-24 查到 370 筆）
- **最大的好消息：這家不像典型獵頭那樣把客戶名稱藏起來。**
  職缺頁的 `<meta property="og:title">` 直接就是
  `「職稱－公司全名｜HuntByte」`，`og:description` 還附了地點跟聘用類型。
  **不用反推、不用猜，讀 meta tag 就有答案**，信心可以直接標 `high`。
- 純 `curl` 級的 HTTP request 就抓得到，**是伺服器端渲染的頁面，不用瀏覽器**。
  之前以為要用瀏覽器（Playwright 開了幾頁確認過內容存在），後來發現
  `curl` 一樣拿得到同樣的 `<meta>` 標籤，改用 `curl` 效率高很多、也不會有
  瀏覽器自動化的額外風險。
- 抓取程式：`jobintake/competitor_scan.py` 的 `huntbyte_scan()`。
- 同一家公司常常一次刊好幾個職缺（例：中鼎工程一次 6 筆）——
  **職缺數量本身就是「這家公司現在缺人的急迫程度」的信號**，照 Jacky 的
  優先序（大企業、付得起、中低階量大優先）排序時，職缺數量可以當一個因子。
- ⚠️ **第一次跑（2026-09-24）踩到一個雷**：排名第一的「數位獵人科技股份
  有限公司」一次刊了 69 筆，職稱大多掛「【代徵】」——查了才發現這家
  **自己就是一家人力仲介**，是它在幫它的客戶刊登，og:title 抓到的是仲介
  自己的名字，不是真正要用人的企業。這種要濾掉，不然會把同業誤當成
  開發目標。`competitor_scan.py` 的 `looks_like_agency()` 就是處理這個：
  公司名稱裡有「獵人／獵頭／人力銀行／人力仲介」這類字，或者這家底下
  的職缺有一半以上標「代徵」，就當同業處理，不進開發名單。
  **這個過濾清單目前是憑經驗列的關鍵字，不是窮舉——之後如果看到明顯是
  同業卻沒被濾掉的，把名字或關鍵字補進 `AGENCY_NAME_HINTS`。**

### 2. Robert Walters（robertwalters.com.tw）—— sitemap 能讀，詳情頁被擋死

- Sitemap 索引 `https://www.robertwalters.com.tw/sitemap.xml`
  → 職缺在 `https://www.robertwalters.com.tw/advert_links.xml`
  （2026-09-24 查到 450 筆）。**這層可以讀，不會被擋。**
- **職缺標題本身常常已經匿名成「外商電源大廠」「半導體製造業龍頭」
  「隱形冠軍」這種說法**（跟 Jacky 原本描述的情況一致），對照
  URL 分類路徑（例：`/electronicsmanufacturingindustrialindustries/jobs/firmware/`）
  可以抓到產業別。
- ⛔ **詳情頁被 PerimeterX 擋住**，2026-09-24 實測：純 `curl` 抓幾頁後開始
  回 CAPTCHA 頁；換成**真的 Playwright 瀏覽器**開同一頁，直接回
  `403 訪問此頁面已被拒絕`（PerimeterX 連正常瀏覽器都擋，不是只擋沒有
  JS 的請求）。**這是「遇到驗證碼就停」的界線，沒有嘗試繞過。**
- 目前處理方式：**只用 sitemap 網址裡的職缺標題做反推**（標題本身的線索＋
  產業分類），信心最高只能標 `medium`，因為沒有詳情頁的完整敘述（薪資、
  地點、產品線）可以佐證。程式：`competitor_scan.py` 的 `robertwalters_titles()`。
  ⚠️ 2026-09-24 實測過一筆（「外商電源大廠」+「Senior/Staff MCU FW Engineer」）：
  用 WebSearch 交叉比對，符合「外商＋電源＋Taipei」輪廓的候選至少有
  Schneider Electric、Renesas、AMD、Trend Technologies 四家，**沒有一個
  查得出決定性證據**——這代表光靠 RW 的標題做反推，很多時候只能縮小
  範圍到幾家候選，**推不到單一答案就是推不到，照規矩標 `未知` 或最多
  `low`，不要為了交差硬選一家。**這也印證了為什麼詳情頁被擋是真的傷：
  沒有薪資、地點、產品線這些細節，光憑標題常常不夠鎖定單一公司。
- 如果之後真的需要詳情頁內容，選項是「人工開瀏覽器看幾筆重要的」，
  不要寫自動化去硬闖——那條路已經被連續兩種方法擋下來，代表對方是
  刻意防的，不是技術疏漏。

### 3. RecruitFirst（recruitfirst.co）—— 找到職缺頁了，但台灣職缺很少

- 職缺清單頁是 `https://www.recruitfirst.co/jobs-vacancies/`（不是 sitemap
  能找到的，是從首頁導覽列的「Job Seekers」連過去的，用瀏覽器點過一次才找到）。
  沒有 sitemap，是一個可篩選的清單頁＋分頁（共 71 頁），職缺詳情網址格式
  `https://www.recruitfirst.co/job-details/?id=NNNNN`。
- 這家是東南亞區域型人力公司，清單裡**大多數是馬來西亞、新加坡、香港、
  印尼、韓國的職缺**，台灣的很少（用 Area/District 篩「Taiwan Region」才篩得出來）。
  優先順序上排在 HuntByte 後面。
- **會匿名客戶**：詳情頁有一段「Who you'll be working for」，寫法類似
  Robert Walters（例：「The client is an intelligent automation solutions
  and industrial robotics MNC with subsidiaries across the APAC region.」），
  要反推公司需要交叉比對，信心最高只能標 `medium`。
- 沒有遇到驗證碼或擋爬蟲，用瀏覽器或 `curl` 應該都能讀，但這支程式目前
  **還沒寫自動化**（只手動確認過結構），下次要用的人可以照 HuntByte 那支
  的寫法，改成打 `jobs-vacancies/` 分頁＋篩 Taiwan Region。

### 4. H&L 智理（hnl-consultants.com）—— 查過，沒有公開職缺清單頁

- `sitemap_index.xml`（robots.txt 裡兩個 sitemap 網址都試過，
  `wp-sitemap.xml` 抓不到東西，`sitemap_index.xml` 才是對的）。
- 底下 `post-sitemap.xml` 全部是部落格文章（「為什麼要和獵頭合作」
  「最佳工作方法」之類），`headhunter-case-sitemap.xml`／
  `job-seeker-case-sitemap.xml` 是案例分享頁，**不是即時的職缺清單**。
- **判斷：這家可能沒有公開陳列個別職缺的頁面**（服務模式可能是純顧問媒合，
  不對外貼職缺）。先不列入這個方法的來源，除非之後發現別的入口。

## 反推公司的判斷方式（信心分級）

| 信心 | 什麼情況 | 能不能直接進開發名單 |
|---|---|---|
| **high** | 來源網站直接寫出公司全名（例：HuntByte 的 og:title） | 可以，但寄信前仍要過 `client_guard` |
| **medium** | 標題／內文有具體線索（產業、產品、規模、廠區），但沒有直接寫名稱，需要交叉比對新聞或 104 才能猜出來 | 先進 `company_leads`，寄信前要顧問或 Jacky 看過反推依據 |
| **low** | 只有籠統形容（「知名企業」），交叉比對也查不出具體對象 | 不進開發名單，留著當產業訊號參考就好 |

**推不出來就老實標 `未知`，不要硬猜**——這條規矩跟 `contact_lookup.py`
查信箱是同一個道理：編一個錯的比沒有更糟，因為沒人會發現錯在哪，
直到真的寄錯信或聯絡錯人。

## 資料寫去哪裡

- 反推出來的公司線索寫進 D1 的 `company_leads` 表，`source_kind` 標來源
  （`huntbyte` / `robertwalters` / 之後其他來源各自的代號），
  `signal` 欄位寫清楚是從哪個職缺、什麼線索反推出來的，方便之後回頭查證。
- **這張表是線索池，不是開發名單。** 要正式寄開發信之前，還是要走
  `bd_tick.py` 那一套（過 `client_guard` → `contact_lookup` 查窗口 →
  `draft_bd` 寫信 → 顧問核准），不能從 `company_leads` 直接跳去寄信。

## 2026-09-24 第一次跑的結果

- HuntByte：370 筆職缺、122 家公司（去重後），濾掉 1 家同業仲介
  （數位獵人科技，職稱大量標「代徵」），過 `client_guard` 沒有命中既有客戶，
  **121 家寫進 `company_leads`**（`source_kind='huntbyte'`）。
- Robert Walters：450 筆職缺標題讀出來了，但詳情頁被擋，**沒有寫進
  `company_leads`**——標題本身信心不夠、沒有交叉比對過，不想把一堆
  「可能是這家、也可能是那家」的猜測混進線索池，之後如果要用這批，
  建議先請顧問人工看幾筆有明顯商機的再個別處理，不要整批自動寫入。
- RecruitFirst／H&L：這次沒有產出線索（結構找到了但沒寫抓取程式／
  沒有可用的職缺頁），下次要用的人接手前面「還沒解決」那幾段。

⚠️ **排前面的名單裡有幾家職缺其實是海外據點的**（例：VILA BUSINESS INC.
是澳洲雪梨的職缺、阜爾運通有幾筆是泰國職缺）——`company_leads` 的
`signal` 欄位只寫了職缺數量跟前幾個職稱，**沒有自動判斷是不是海外職缺**，
顧問要用這批名單之前，麻煩先掃一眼職稱有沒有地名（雪梨／泰國／菲律賓
這種），海外職缺不是 Step1ne 現在做的業務範圍。

## 怎麼重新跑一次

```bash
cd jobintake
# 先看結果，不寫資料庫
python3 competitor_scan.py
# 確認沒問題之後才寫進 company_leads
python3 competitor_scan.py --write
```

跑之前檢查 `huntbyte_job_urls()` 抓到的筆數有沒有明顯異常（暴增或歸零），
異常代表網站結構可能改了，要重新核對 `og:title` 的格式還在不在。
