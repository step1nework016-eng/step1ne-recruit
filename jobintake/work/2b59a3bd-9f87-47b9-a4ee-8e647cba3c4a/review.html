一、我擋掉了什麼

規則式禁刊掃描：0 條命中（來源沒有可掃的內容，不是「掃過確認乾淨」）。

我另外擋掉的，是流程本身的風險：

我擋掉的為什麼
用常見職缺範本把 title／薪資／工作內容／應徵條件補滿這些是會被求職者當成僱傭條件看的資訊。編出來的薪資帶與工時，等於刊登不實勞動條件，人選投遞後才發現不符，客訴與商譽風險都落在你身上
憑「私人協助」推測產業或客戶名寫進 client_nameclient_named=1 是「允許具名」，不是「已經知道名字」。沒拿到公司全名就寫，會寫錯公司
生一個 slug 與 page_titleslug 格式要求 <領域>-<職務>-<地點>-<區隔>，四個維度我一個都沒有。生 dedupe-test-1 這種看不出差別的 slug，正好是規範明列的反例（game-cs-2／game-cs-b／game-cs-new）
生 FAQ 與「為什麼選這個機會」這兩塊全靠職缺實質內容支撐，沒有內容就只會產出空話，對 AEO 也沒有幫助

另外提醒兩件與這一筆設定綁在一起、之後產內容時我會盯的：

1. ai_disclosure = never → 頁面與應徵流程不得出現「AI 面談」「阿財」「自動化初談」字樣，

一律寫成中性描述（例：「初步電話／線上訪談，由顧問安排」）。

2. 報告品牌 none → 客戶版報告標題只寫「人選推薦」，不放 logo，

頁尾拿掉德仁管理顧問／統編／就服許可證，聲明段落也不得提及任何公司名。

注意：這只約束客戶版報告，履歷本身仍具名。

二、待顧問確認

以下每一項求職者都一定會問，來源全部未提供。打星號的是沒有就不能上架的：

必要（缺一不可）

  • ★ 對外職稱
  • ★ 工作地點（縣市／區／完整地址）
  • ★ 工作內容（3–5 條主要職責）
  • ★ 薪資：具體區間，或明確指定「依經驗面議」

    • - 若客戶給的是學歷分級表（例：普通大學 35K／前四大 43K），只公開總區間，

    分級細節不上頁面，避免被解讀成學歷歧視

  • ★ 僱傭型態確認：正職代招 → 直聘正職（FULL_TIME），請確認不是派遣或約聘
  • ★ 客戶公司全名（client_named=1，可具名，但我需要拿到正式名稱）

    • 求職者必問（沒有就頁面會顯得可疑）

  • 需求人數
  • 學歷要求／年資下限
  • 必要條件與加分條件（技能、工具、語言、證照）
  • 上班時間、班別、是否輪班、加班常態與加班費計算
  • 休假制度（週休二日？排休？）
  • 出差需求與比例
  • 福利（三節、年終、保險、補助）
  • 產業別（industry，職缺卡分類用）
  • 面試流程與關卡數

    • 私人協助案特有、建議先跟客戶對過

  • 這個缺可不可以公開刊在 step1ne.com？（「朋友認識・私人協助」有時候客戶只想私下找人，

    • 不希望職缺被同業或自家員工看到。若是，就不走上架流程，改走私下媒合。）

  • 客戶願意具名到什麼程度：公司全名？還是只寫集團／品牌名？

    三、服務線與同名職缺

    服務線：正職代招（標準版頁面） — 依你的指定，我沒有改判。

    供你日後核對的判定理由：一般企業委託代招正職，標籤寫「正職」、走標準版版型。

    另外兩條線這次都不適用——沒有年薪百萬／主管職／保密需求（高階獵才），

    雇主也不是我方、沒有轉正條件（人力派遣），所以不加「顧問保密初談」FAQ，

    也不加「派遣權益跟正職一樣嗎？」FAQ。

    同名職缺區隔（Phase 4.5）：本次未執行。

    沒有職稱就無法對 D1 jobs 表下 title LIKE 查詢，區隔維度也無從挑起。

    等你補上職稱與地點後，我會先跑：

    bash

    npx --yes wrangler d1 execute step1ne-recruit --remote \

    --command="SELECT slug,title,locations,employment,salary_min,salary_max FROM jobs WHERE title LIKE '%<職稱關鍵字>%';"

    若查到同職稱，我會依序從班別 → 薪資帶 → 僱傭型態 → 外語加給 → 地點挑區隔維度，

    寫進 H1、<title>、meta description 與導言第一句，避免兩頁 SEO 互搶；

    並確保申請表下拉選單文字與頁面標題完全一致（含區隔字串），

    以免面談抓錯 JD、報告歸錯客戶。

    不會用的區隔方式：公司名、客戶代稱（甲／乙、A 廠／B 廠）、client_code、流水號。

    即使這筆 client_named=1 可以具名，同名職缺的區隔也不走「用公司名分」——

    一旦站上並列兩則同職稱職缺、其中一則具名，等於把另一則未具名客戶的存在與招募動向

    一起曝光給同業。區隔一律用求職者分得出來的實質差異。
