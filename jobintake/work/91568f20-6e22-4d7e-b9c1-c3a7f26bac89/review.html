一、我擋掉了什麼

規則式禁刊掃描沒有命中任何一條，我自己再逐條比對 Phase 2 的五類禁刊，結果如下：

禁刊類型本件狀況
委任客戶公司名稱無可判定。client_named = 1（已簽約可具名），但來源根本沒給公司名，所以頁面上目前也寫不出來。等你補了公司名，因為可具名，不需要匿名化改寫。
歧視性條件（國籍／年齡／性別／婚育／容貌）無。來源沒有任何條件敘述。
內部獵頭搜尋策略無。
內部溝通備註無。
標註「待確認」的欄位嚴格說，整份都是待確認，見第二段。

規則掃不到、但我認為必須擋下來的一項：

  • 來源本身就不是職缺資料。 DEDUPE-TEST-2 看起來是你在測重複偵測／流程串接時

    • 丟進來的測試 payload。這種輸入最危險的失敗模式，是 AI 為了「產出完整頁面」自行

    腦補職稱、薪資、工作內容，產出一份看起來很完整、實際上整份都是編的 JD——一旦上線，

    求職者投遞的是不存在的缺，阿財（AI 面談）也會拿假條件去面談、報告還會歸錯客戶。

    所以我主動中止產稿，只寫出空殼 spec 並在 notes 標「不可上架」。

  • 順帶一提：如果這確實是測試件，建議測完後從佇列刪除，不要讓它留在 jobs 表裡，

    • 免得日後有人誤以為是真缺而接手上架。

    二、待顧問確認

    以下每一項求職者都一定會問，而來源全部沒有。這不是挑剔，是這份稿子連骨架都還沒有：

    最低限度、缺了就無法上架的（必填）

    1. 對外職稱——決定 title、slug、H1、<title> 與申請表下拉選單文字，是所有欄位的源頭。

    2. 公司名稱——本件 client_named = 1 可具名，但你沒給名字。是否確實要具名寫出？

    3. 工作地點——完整地址／至少縣市＋區（locality / region / locations）。

    4. 薪資——具體區間，或明確是「依經驗面議」。

    - 若客戶給的是學歷分級表（例：一般大學 35K／前段校 43K），只公開總區間，不公開分級細節，避免被解讀成學歷歧視。

    - 純面議則頁面寫「依經驗面議」，schema 不放 baseSalary。

    5. 工作內容——至少 3–5 條，我才有辦法改寫成求職者視角（不會直接貼客戶原文）。

    6. 必要條件 / 加分條件——含年資、學歷、語言、證照。

    會影響求職者投或不投、強烈建議補的

    7. 上下班時間、班別（早／中／晚／輪班）、加班常態與加班費計算方式

    8. 休假制度（週休二日？排休？）

    9. 需求人數

    10. 是否需出差、外派、駐點客戶端

    11. 福利（三節、年終、保險、教育訓練、交通／伙食補助）

    12. 產業別（industry）與職缺卡分類鍵（cat）——決定它掛在職缺專區哪個篩選按鈕下

    13. 面談流程說明——本件 ai_disclosure = never，所以流程要用中性描述（例：「初步電話／線上訪談」），

    頁面與通知信一律不得提到 AI 面談、不得寫「阿財」。

    已由你決定、我不動也不再問（記錄備查）

    三、服務線與同名職缺

    服務線判定：正職招募（正職代招・標準版）

    理由：這是你在派件時直接指定的，我不覆蓋。用 Phase 3 的訊號回頭驗算也不衝突——

    來源沒有「派遣雇主是自家公司／有轉正條件／時薪制基層職」的派遣訊號，也沒有

    「年薪百萬以上／主管職／需保密」的高階獵才訊號，沒有訊號指向另外兩條服務線，

    所以維持正職。頁面走標準版：標籤「正職」，不加派遣權益 FAQ，也不加

    「我還在職，投遞會不會曝光？」那類高階獵才 FAQ。

    對應寫進 spec 的只有 employment: ["FULL_TIME"] 與 track: "fulltime" 兩項——

    這是唯一能從你已確認的服務線安全推導出來、不涉及任何猜測的欄位。

    同名職缺區隔：本次無法執行

    Phase 4.5 要求「先查再寫」，但比對的起點是對外職稱，本件沒有職稱，

    D1 的 SELECT ... FROM jobs WHERE title LIKE '%…%' 連查詢字串都組不出來，

    因此這一關跳過，未執行，不是「查過沒有重複」。等你補上職稱後我會補跑。

    補跑時會做的事，先講清楚，你補資料時可以順便把區隔想好：

    1. 查 D1 有無同／近似職稱的既有職缺。

    2. 若有，只用求職者分得出來的維度區隔，優先序：班別 → 薪資帶 → 僱傭型態 → 外語加給 → 地點。

    絕不用「A 公司／B 公司」「甲客戶」或編號——那等同洩漏客戶，跟直接寫公司名一樣違規。

    3. slug 依 <領域>-<職務>-<地點>-<區隔> 命名，要能自我說明；不接受 xxx-2、xxx-b、xxx-new。

    ⚠️ 特別提醒：DEDUPE-TEST-2 這串字不可以流進 slug 或任何對外欄位。

    4. 若兩頁高度相似，判準是「求職者會不會兩個都投？」——會就分兩頁並讓標題／導言／

    工作內容有實質差異（區隔字串要進 H1、<title>、meta description 與導言第一句）；

    不會就合併，或次要頁掛 canonical 指向主頁，避免關鍵字互搶導致兩頁都排不上。

    5. 申請表下拉選單文字必須＝頁面標題（含區隔字串），否則阿財會抓錯 JD、報告歸錯客戶。
