# 人才庫配對（匿名短名單）

用途：顧問在開發客戶、客戶還沒開職缺時，先確認人才庫裡有沒有這類人。
結果一律是匿名的（沒有姓名、電話、email、LINE、完整履歷）。

## 鐵則（先看這段）

- 只能用下面的 curl 呼叫配對服務。不准要求、也不准嘗試列出一大批人、匯出履歷、把名單存成檔案。
- 權杖放在環境變數 `S1NE_TOKEN`。絕對不要印出、echo、寫進檔案、貼進對話。
  - 檢查有沒有設，只能用：`[ -n "$S1NE_TOKEN" ] && echo 有設定 || echo 沒設定`（Windows PowerShell：`if ($env:S1NE_TOKEN) {"有設定"} else {"沒設定"}`）。
  - 沒設定就停下來，告訴她：用「平常登入後台的那組權杖」設定。Mac/Linux 在終端機執行 `export S1NE_TOKEN='權杖'`（要永久生效就寫進 ~/.zshrc）；Windows PowerShell 執行 `setx S1NE_TOKEN "權杖"` 後重開 Claude Code。權杖不要貼到聊天裡。
- 每一輪對話最多查 3 次。不准用迴圈、換一堆關鍵字去把整個人才庫「掃」出來。
- 如果她要求「全部列出」「匯出履歷」「給我姓名電話」：拒絕，說明這是資安規定，請她到後台卡片看單一人選。
- 絕不推測年齡、性別、國籍。資料沒寫就寫「資料沒寫」。
- 只做草稿、查詢，絕不代為寄出任何信件或訊息。

## 流程

### 1. 先確認需求（只問一次，一則訊息）
她描述客戶需求後，先用白話複述，並整理成：
- 必要條件關鍵字（缺一個就不算符合，最多 6 個）
- 加分關鍵字（最多 8 個）
- 產業（最多 4 個）
- 年資層級：junior（3年內）／mid（3-8年）／senior（7年以上）／不限
請她回「OK」或修正。她確認後才查。

### 2. 查詢
用 curl（`<名字>` 換成她自己的名字拼音，例如 phoebe，用來留稽核紀錄；JSON 內的中文直接寫）：

```
curl -s -X POST "https://step1ne-backoffice-worker.aiagentg888.workers.dev/admin/talent-match" \
  -H "authorization: Bearer $S1NE_TOKEN" \
  -H "content-type: application/json" \
  -H "x-consultant-label: <名字>" \
  -d '{"need":"客戶需求一句話","must_keywords":["..."],"nice_keywords":["..."],"industries":["..."],"seniority":"any","limit":10}'
```
Windows PowerShell 請改用 `Invoke-RestMethod`，標頭同上，權杖用 `$env:S1NE_TOKEN`。
回傳 401 代表權杖錯誤；429 代表查太頻繁（每人每小時 30 次），請她稍後再試。

### 3. 呈現結果（繁體中文，短表格）
欄位：代號、來源、方向、年資、期望薪資、地區、亮點、信心、卡片連結。
- 「信心」照回傳值寫。信心為「低」的，要明講：「這幾位有必要條件在履歷找不到（unverified_must），不能當成符合」，並列出缺哪些。
- 只能說「比對到哪些關鍵字」，不要說「很適合」「完全符合」。關鍵字比對不等於真的有這個能力。
- 沒資料的欄位寫「資料沒寫」。
- 來源是「應徵／履歷在庫」的，連結點開後台卡片（用她平常登入後台的帳號）；來源是「AI 找到」的，連結欄是指引：到後台「AI 找的人」分頁，用編號對應。
- 結果少於預期就直接說少，不要為了湊數放寬必要條件、也不要連續換關鍵字重查來「湊」。

### 4. 下一步（讓她選）
- 到後台開卡片看細節。
- 幫她擬一句給客戶的匿名話術草稿，例如：「我們手上目前有 3 位具備〇〇背景、年資約 5-8 年的人選」。只能用人數、背景、年資區間；不放公司名、學校名、代號、薪資、地區細節、任何能認出個人的資訊。只給草稿，由她自己決定寄不寄。

### 5. 提醒
- 提到客戶時，客戶名稱請照統編登記的全名。
- 結果是匿名短名單，不是推薦名單；要正式推薦，請走後台卡片與正常流程。
